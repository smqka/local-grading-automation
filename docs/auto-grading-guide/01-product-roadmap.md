# 产品路线图

## 0. 立项前确认

目标：确认这个工具能在合理、合规、安全的边界内帮助老师节省批阅时间。

必须确认：

- 使用场景：老师只批整张卷子的某一道题，电脑端能打开爱探究小程序或网页。
- 界面稳定性：学生答案区域和打分区域位置稳定。
- 授权边界：老师本人授权本机工具辅助批改，不共享账号密码。
- 数据边界：默认只处理当前题目的学生作答截图，不处理全卷、名单、班级表。
- 评分边界：AI 输出建议，老师负责最终评分。

本阶段产物：

- 一份题目样例。
- 一份评分规则样例。
- 20 到 50 份已批改学生答案作为离线验证样本。
- 学校或老师对试点范围的明确许可。

不满足则暂停：

- 不能在电脑端稳定打开阅卷界面。
- 答案区域不稳定，无法稳定裁剪。
- 必须绕过平台限制才能使用。
- 无法避免上传学生身份信息。

## 1. 网页端 MVP

目标：验证“网页捕获窗口 + 裁剪答案区域 + AI 建议分”的闭环。

老师使用流程：

1. 老师在电脑微信或网页端打开爱探究批阅页面。
2. 老师在 Chrome 或 Edge 打开本工具网页。
3. 老师点击“开始捕获”，在浏览器弹窗中选择爱探究窗口。
4. 老师首次框选学生答案区域。
5. 老师输入本题满分、标准答案和给分规则。
6. 老师点击“识别当前答案”。
7. 工具返回建议分、扣分理由、置信度和复核提示。
8. 老师在爱探究中手动录入分数。

本阶段只做：

- 浏览器屏幕捕获。
- 答案区域手动框选。
- 单题评分规则录入。
- 单份答案识别。
- 建议分展示。
- 本地配置保存。

本阶段不做：

- 自动点击爱探究。
- 自动提交分数。
- 保存爱探究账号密码。
- 批量无人值守处理。
- 逆向爱探究接口。

通过标准：

- 老师能在 1 分钟内完成题目规则配置。
- 截图裁剪区域稳定。
- 单份答案从点击识别到返回建议不超过 10 秒。
- 对试点题目，AI 建议分与老师最终分差距在可接受范围。

## 2. 半自动连续批阅

目标：减少重复点击和重复录入，但仍保持老师确认。

新增能力：

- 自动检测画面变化，提示“发现新答案”。
- 保留上一题的评分规则和裁剪区域。
- 支持快捷键触发识别，但仅在工具页面获得焦点时生效。
- 支持“上一份/下一份”的批阅记录查看。
- 对低置信度答案强制标记为“人工复核”。

仍然禁止：

- 无人值守自动提交。
- 处理验证码或风控页面。
- 在没有老师确认的情况下操作爱探究。

通过标准：

- 老师不需要重复配置同一道题。
- 连续批 20 份时工具无崩溃、无串题、无错裁剪。
- 低置信度样本能够被明显标出。
- 老师主观感受确实省时间。

## 3. 一键填分候选阶段

目标：在老师明确确认后，工具辅助把分数填入爱探究。

建议实现形态：

- 纯网页端继续负责评分和确认。
- 另加桌面小助手或浏览器扩展负责窗口定位、点击或输入。
- 每次填分前必须显示“将填入 X 分”。
- 老师点击确认后才执行。

准入条件：

- MVP 已验证评分质量。
- 老师能接受一键填分操作。
- 已确认该操作不违反平台使用规则或学校要求。
- 已设计暂停、撤销、异常中断和日志追溯机制。

必须保护：

- 分数不能超过满分。
- 分数格式必须符合爱探究输入要求。
- 识别到页面变化、网络卡顿、弹窗、验证码时立即暂停。
- 工具不能自动处理异常登录和身份验证。

## 4. 官方 API 接入候选阶段

目标：如果爱探究或学校提供正式接口，改用授权 API 替代屏幕捕获。

只在以下条件满足时推进：

- 爱探究或学校提供正式接口文档。
- 有明确授权范围。
- 有测试环境或沙箱账号。
- 有接口调用日志和错误回滚机制。
- 有数据处理协议或等效授权文件。

需要的接口：

- 获取批阅任务。
- 获取匿名化学生作答图片。
- 获取题目信息和满分。
- 提交建议分或最终分。
- 查询/修改分数。
- 操作日志和回滚。

仍然建议：

- 第一阶段 API 接入也只提交“建议分”或“老师确认后的分数”。
- 不直接开放全自动批阅。

## 5. 长期产品化阶段

目标：从个人辅助工具升级为可维护、可审计、可部署的教育场景工具。

需要补齐：

- 用户权限系统。
- 学校/老师授权管理。
- 数据保留策略。
- 模型版本管理。
- 评分规则版本管理。
- 操作审计。
- 异常申诉和复核流程。
- 安全测试。
- 法务和隐私评估。

只有在这些补齐后，才考虑给更多老师或学校使用。
