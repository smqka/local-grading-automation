# 产品路线

## 阶段 1：手动建议分

目标：验证模型能根据单张答案截图和文字规则返回可用建议分。

准入条件：

- 支持窗口捕获和答案区域裁剪。
- 支持手动输入标准答案、满分、给分规则和扣分规则。
- 支持结构化返回建议分、置信度、不确定因素和复核标记。
- 低置信度或非法分数强制人工复核。

不做：

- 不保存账号密码。
- 不调用非公开接口。
- 不自动点击分数。

## 阶段 2：坐标辅助点击

目标：用户记录阅卷系统中分数按钮坐标，高置信度时自动点击分数。

准入条件：

- 鼠标自动化只在 `127.0.0.1` 本机服务中执行。
- 用户必须主动启用自动点击。
- 每个分值坐标由用户手动记录。
- 模型返回前不得执行任何点击。

## 阶段 3：半自动批卷循环

目标：同一道题连续批改。

流程：

1. 刷新当前裁剪截图。
2. 等待模型返回。
3. 达到阈值则点击分数。
4. 低于阈值则等待审核或自动跳过。
5. 翻页后延迟刷新下一份截图。

关键约束：

- 自动打分只点分数；如果阅卷系统自动翻页，不再点下一份。
- 自动跳过只在用户选择低置信度自动跳过时执行。
- 暂停或重新继续后，旧请求返回不得触发点击。

## 阶段 4：稳定性和场景适配

目标：针对不同阅卷系统和题型提高稳定性。

可改进方向：

- 页面变化检测替代固定翻页延迟。
- 自动检查裁剪区域是否变化。
- 批次记录和复核列表。
- 多题型规则模板。
- 自有对象存储临时 URL 服务。
