# 网页端自动化技术设计

## 设计目标

在不接入爱探究 API、不保存账号密码、不上传手动截图的前提下，通过网页端捕获电脑微信或浏览器中的爱探究窗口，辅助老师批阅当前题目。

## 能力边界

网页端可以做：

- 请求老师授权选择一个屏幕、窗口或标签页进行捕获。
- 从捕获画面中裁剪学生答案区域。
- 将裁剪图发送给后端进行 AI 评分。
- 显示建议分、扣分理由和置信度。
- 保存题目规则和裁剪区域配置。

网页端不能可靠做：

- 静默读取爱探究窗口。
- 永久保存屏幕捕获权限。
- 在老师未交互时自动开始捕获。
- 系统级置顶悬浮。
- 全局快捷键。
- 稳定控制电脑微信小程序点击和输入。

因此第一版只做“捕获 + 评分建议”，不做“自动录分”。

## 推荐技术方案

### 前端

主要模块：

- 捕获模块：调用 `navigator.mediaDevices.getDisplayMedia()`。
- 画面预览：展示当前捕获窗口。
- 区域框选：让老师框选学生答案区域。
- 裁剪模块：用 Canvas 从视频帧中裁剪答案区域。
- 题目配置：满分、标准答案、给分规则、扣分规则。
- 评分结果：建议分、理由、置信度、复核标签。
- 本地设置：保存裁剪区域、最近题目配置。

浏览器要求：

- Chrome 或 Edge。
- HTTPS 环境，或本地开发环境。
- 老师每次开始捕获都需要主动授权。

### 后端

主要模块：

- 鉴权或本地访问保护。
- 接收裁剪后的答案图片。
- 调用 AI 模型。
- 返回结构化评分结果。
- 记录最小必要日志。
- 管理 API key 和环境变量。

后端必须持有 API key，前端不得持有。

### 数据流

1. 老师打开爱探究批阅页面。
2. 老师打开本工具网页。
3. 老师点击“开始捕获”。
4. 浏览器弹窗让老师选择爱探究窗口。
5. 工具展示预览画面。
6. 老师框选学生答案区域。
7. 工具从当前视频帧裁剪答案区域。
8. 前端显示裁剪预览，供老师确认。
9. 前端把裁剪图、题目规则、满分发送给后端。
10. 后端调用 AI 服务。
11. 后端返回评分 JSON。
12. 前端展示建议分和理由。
13. 老师自行在爱探究录分。

## 评分请求格式

建议前端发送：

```json
{
  "question_id": "local-question-001",
  "max_score": 6,
  "standard_answer": "老师填写的标准答案",
  "rubric": "老师填写的给分规则",
  "image": "裁剪后的答案区域图片",
  "mode": "suggest_only"
}
```

建议后端返回：

```json
{
  "suggested_score": 4,
  "max_score": 6,
  "confidence": 0.82,
  "review_required": true,
  "reasons": [
    "计算过程第二步符号错误",
    "最终答案与标准答案不一致"
  ],
  "detected_answer_summary": "模型看到的学生解题过程摘要",
  "warnings": []
}
```

## 画面捕获与裁剪

第一版采用手动框选：

- 老师第一次框选学生答案区域。
- 同一道题后续复用同一裁剪区域。
- 每次识别前展示裁剪预览，避免错裁。

后续可升级：

- 通过模板匹配定位答案区域。
- 通过边缘检测或 OCR 辅助定位。
- 通过画面差异检测提示新学生答案出现。

必须避免：

- 捕获整个桌面后直接上传整屏。
- 上传含学生姓名、班级、聊天消息、通知弹窗的画面。
- 裁剪区域越界或包含分数输入区。

## 自动检测新答案

可在第二阶段实现。

基本思路：

- 按固定间隔从视频流取帧。
- 只比较答案区域图像差异。
- 差异超过阈值并稳定一段时间后，提示“疑似新答案”。
- 老师确认或点击识别。

注意：

- 不要在页面还在加载时自动评分。
- 不要连续重复提交同一张答案。
- 需要显示“当前识别的是哪一次捕获”。

## 自动录分暂缓

纯网页端无法稳定控制电脑微信小程序里的按钮。若后续要做自动录分，建议另开阶段：

- 浏览器扩展：适合爱探究有网页端且 DOM 可访问的情况。
- 桌面小助手：适合电脑微信小程序，需要窗口定位和坐标操作。
- 官方 API：最稳定，但需要平台授权。

任何自动录分都必须满足：

- 老师确认后执行。
- 分数不超过满分。
- 页面异常立即停止。
- 有操作日志。
- 有暂停按钮。

## 开发顺序

1. 搭建前端基础页面。
2. 实现屏幕捕获和预览。
3. 实现答案区域框选。
4. 实现 Canvas 裁剪和本地预览。
5. 搭建后端评分接口。
6. 接入 AI 模型。
7. 返回结构化评分结果。
8. 加入错误处理和超时。
9. 加入本地题目配置保存。
10. 做 20 到 50 份样本验证。

## 主要风险

| 风险 | 影响 | 应对 |
| --- | --- | --- |
| 浏览器不支持屏幕捕获 | 无法使用 | 推荐 Chrome/Edge |
| 老师选错窗口 | 错误评分 | 捕获后显示预览 |
| 裁剪区域含姓名 | 隐私风险 | 预览并支持遮挡 |
| AI 误判过程分 | 评分风险 | 只给建议，低置信度复核 |
| API key 泄露 | 资金和数据风险 | 后端持 key，立即轮换泄露 key |
| 爱探究界面变化 | 裁剪失效 | 每次显示裁剪预览 |
