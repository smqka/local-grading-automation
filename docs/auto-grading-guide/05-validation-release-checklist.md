# 验证与发布清单

## 本地开发前检查

- Git 仓库已初始化。
- `.gitignore` 已忽略 `.env`。
- `.env.example` 不包含真实密钥。
- 真实 API key 已轮换并只放在 `.env`。
- 没有真实学生图片放在仓库内。
- 没有老师账号密码放在仓库内。

## MVP 功能验收

必须通过：

- 可以在 Chrome 或 Edge 中启动屏幕捕获。
- 老师能选择爱探究窗口。
- 工具能显示捕获预览。
- 老师能框选答案区域。
- 工具能裁剪出正确答案区域。
- 上传前能预览裁剪图。
- 后端能返回结构化评分结果。
- AI 建议分不会超过满分。
- AI 低置信度结果会提示复核。
- 工具不会自动提交分数。

## 隐私验收

必须通过：

- 裁剪图默认不包含姓名、班级、学号。
- 服务端默认不保存答题图片。
- 日志不包含 API key。
- 日志不包含老师账号密码。
- 日志不包含完整学生身份信息。
- 可以清除本地保存的题目配置。
- 捕获权限由老师主动点击触发。

## 试点流程

试点建议：

1. 选择一位老师。
2. 选择一道题。
3. 选择 20 到 50 份已批改答案。
4. 先离线对比，不影响真实成绩。
5. 记录工具建议分和老师原分。
6. 汇总误差。
7. 调整评分规则。
8. 再做一次小样本验证。
9. 老师确认可用后，再进入真实辅助批改。

试点期间禁止：

- 自动提交分数。
- 批量无人值守处理。
- 上传含姓名和班级的整屏截图。
- 给未参与试点的老师开放。

## 上线准入建议

满足以下条件再给老师真实使用：

- 老师明确知道 AI 只是建议。
- 老师能独立停止捕获。
- 连续 20 份答案裁剪无错位。
- 建议分无明显系统性偏高。
- 低置信度样本能被拦截。
- 单份识别时间可接受。
- 发现错误时不影响爱探究原始数据。

建议数据指标：

- 误差不超过 1 分比例达到老师可接受水平。
- 高估严重错误样本接近 0。
- 平均耗时比纯人工明显降低。
- 老师认为操作负担低于节省的时间。

## 异常处理

遇到以下情况必须暂停识别：

- 捕获窗口变化。
- 爱探究页面刷新或加载中。
- 出现验证码、登录页、风控页。
- 裁剪区域为空白。
- 图片明显模糊。
- AI 返回非法分数。
- 后端超时。
- 同一答案重复提交多次。

暂停后提示老师重新确认窗口和裁剪区域。

## 自动录分前置清单

只有准备做第二或第三阶段时才使用。

必须满足：

- 老师明确同意一键填分。
- 学校或平台规则允许。
- 已有足够试点数据证明建议分可靠。
- 每次填分都需要老师确认。
- 支持一键暂停。
- 支持查看最近操作。
- 分数写入前再次校验满分。
- 页面异常时不点击。
- 不处理验证码和风控。

如果无法确认平台规则，自动录分功能不做。

## 发布后运维

需要保留：

- 错误日志。
- 模型版本。
- 提示词版本。
- 评分规则版本。
- 功能开关状态。

默认不保留：

- 原始学生答题图片。
- 老师账号密码。
- 爱探究 cookie/token。
- 整屏截图。

## 回滚方案

如果出现评分异常：

- 立即关闭 AI 建议功能。
- 保留本地手动批改流程。
- 检查最近模型版本和提示词版本。
- 用样本复现问题。
- 修复后重新试点，不直接恢复。

如果出现隐私或账号风险：

- 立即停止相关功能。
- 删除临时图片和日志中的敏感内容。
- 轮换 API key。
- 检查是否误提交敏感文件。
- 视情况通知相关人员。

## 每次提交前 Git 检查

执行：

```powershell
git status --short
git check-ignore -v .env
```

确认：

- `.env` 被忽略。
- 没有真实答题图片。
- 没有账号密码。
- 没有 API key。
- 文档和代码改动符合当前阶段目标。
